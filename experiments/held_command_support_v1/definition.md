# Repeated-command boundary support audit

Retrospective metadata audit, registered before counting the additional
windows. Earlier model outcomes and action-support limitations are known.
This audit does not test model performance or add a gate to a closed study.

The generator increments segment ID at every scheduled draw, including
when the next action repeats the previous command. The current index uses
equal segment IDs at the endpoints. Hypothesis: some excluded windows
contain an unchanged commanded four-vector throughout, and could supply
additional executed supervision in a separately registered future recipe.
Whether those windows add useful steering class/course support is unknown.

## Frozen scope

- Exactly the shared world-balanced training corpus and the closed
  executed-weight exam named and hashed in `registration.json`.
- All four worlds and every action in each world's existing catalog;
  no favorable-world/action selection. Full corpora only, not train/val
  partitions or new fitted/evaluated models.
- Horizon 32 and warn radius 0.7, with the existing inclusive `[t,t+32]`
  window convention and final-frame exclusion unchanged.
- Original windows: the existing `window_valid` rule. Constant-command
  windows: every recorded command vector in that same inclusive window is
  exactly equal. Recovered windows: constant-command and not original.
  This is commanded intent, not an assertion about PID motion or noise.
- Report original/recovered/union window counts and positive/negative
  window and distinct-course counts, pooled and per world/action. Report
  same-command segment boundaries and true command changes separately.
  Include zero-supported actions. Course counts overlap across classes and
  actions; recovered windows are not new independent courses.

## Instrument and interpretation

Before reading result counts, pass synthetic tests against an explicit
per-window loop, including repeated commands, real switches, exact equality,
endpoint switches, malformed segment metadata and both action catalogs.
Read no pixels or model weights. Validate action IDs against physical
command vectors, finite distances, monotonic segment IDs and input hashes.
Original accepted windows must have constant commands; otherwise stop and
record an instrument/input inconsistency instead of revising old readings.
Original indices/labels must match `_index_samples`, and per-world original
class counts must equal the committed corpus receipts.

This is not a vision experiment: it counts saved command/segment/distance
metadata. The original corpus receipts retain their rendering checks; this
audit makes no claim about new rendering or perceptual sufficiency.

No minimum gain, power claim, confidence interval, training, promotion or
automatic follow-up fit. A null or forward-only recovery is a valid result.
Do not add corpora, change horizons, redraw seeds or edit source data after
seeing the result. Preserve all earlier NO-GOs. A future training hypothesis
requires its own registration, independent exam, frozen guards and support.

Do not implement a future recipe by relabelling all segment IDs here:
`_split_rollouts` also uses `seg.max()==0` to stratify passive courses.
Changing that can change the split as well as supervision. Extra windows
can also change optimizer-step and CF/now sampling counts at fixed epochs;
a future registration must account for those effects explicitly. This
offline audit changes no deployed work in the 512 KB / approximately 8 ms
budget and establishes no additional anticipation.
